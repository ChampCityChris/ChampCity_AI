# SCL06 workflow checkpoint boundary inventory

This inventory classifies active main-process mutation surfaces. A source checkpoint applies only when the workflow has a selected Work Intake SourceLine. The resulting commit records source chronology; the semantic disposition still belongs to the Operator or workflow owner.

| Mutation surface | Classification | Current owner and checkpoint outcome |
| --- | --- | --- |
| Structured Work Intake capture and source preparation | No source checkpoint required for capture; bootstrap source binding | `structuredWorkIntakeService` and the SCL04 bootstrap establish the SourceLine before route work. |
| Structured route Decision after RouteAssessment | Operator disposition checkpoint | `selectStructuredWorkRoute` saves the Decision once, then creates a SCL05 empty disposition revision on the bound SourceLine. |
| Structured implementation completion | Implementation checkpoint | `recordStructuredImplementation` records the ImplementationRecord and checkpoints attributed files before returning review-ready evidence. |
| Structured Work Item human review Decision | Operator disposition checkpoint | `recordStructuredWorkDisposition` commits an empty disposition revision. Validator results and routine machine transitions do not invent an Operator Decision. |
| Legacy Work Intake routing assessment, Architect draft preparation, and reroute recommendation | No source checkpoint required | These are proposals or preparatory artifacts. The later Operator route decision owns chronology. |
| Legacy route selection, override, revision request, and reroute disposition | Operator disposition checkpoint | `decideWorkRoute` writes the canonical decision first, then checkpoints exact Intake, assessment, route, and affected routed evidence. A failed checkpoint leaves the saved disposition visible as pending and blocks route use. |
| Route Architect Assessment and Work Plan review | Operator disposition checkpoint | `workPlanningKernel.review` checkpoints after the canonical review write. The Plan cannot consume an approved Assessment while its checkpoint is pending. |
| Work Item decomposition proposal preparation | No source checkpoint required | Proposal drafts remain mutable until Operator review. |
| Work Item decomposition acceptance or revision request | Operator disposition checkpoint | `workItemDecompositionService.review` checkpoints the reviewed proposal and, on acceptance, the revised Plan and prior Plan history on the same Intake line. |
| Routed Formal Work Card, Repair Work Card, Implementer Report, and validation review | Operator disposition checkpoint | `routedDevelopmentExecutionService` checkpoints after each review mutation and returns its exact receipt. The implementation runner separately owns the implementation checkpoint before review. |
| Routed implementation run | Implementation checkpoint | `codexImplementerExecutionService` and `planExecutor` own the attributed implementation source commit and report receipt. |
| Routed Work Item close return | Integration-owned checkpoint | Existing `routedDevelopmentExecutionService.close` commits the approved contract, report, validation, and close-return evidence at the Work Item boundary. |
| Routed Phase or Plan acceptance | Integration-owned checkpoint when approved; Operator disposition checkpoint when revision requested or rejected | `reviewAcceptance` records nonapproval dispositions immediately and the existing lifecycle checkpoint records an approved closeout, including an empty chronology revision when evidence was committed earlier. |
| Research no-Plan close | Integration-owned checkpoint | `researchCompletionService` records the approved no-Plan Assessment at the research boundary; it can create an evidenced empty chronology revision after Assessment review. |
| Routed Issue RCA review and route reframe | Operator disposition checkpoint | `runWorkIssueAction` checkpoints exact Issue record, investigation, review, and canonical routed assessment after review; a reframe remains on the same Intake line and awaits a separate route decision. |
| Routed Issue correction Fix Card, Phase, aggregate validation, and Issue close | Integration-owned checkpoint | Issue Resolution owns the correction evidence and integration handoff. SCL07 must reconcile those plain Markdown completion artifacts into source chronology; they are not silently treated as committed by the RCA checkpoint. |
| Standalone Issue Resolution and retained `currentWorkflow` Architect, Work Card, Phase, and Project reviews without a Work Intake SourceBinding | No Work Intake source checkpoint required | These retained workflows have no selected Intake SourceLine. Their semantic Markdown disposition remains governed by their existing service. |
| Tester, Validator, regression assessment, and routine machine dispositions | No Operator source checkpoint required | These are machine or Validator facts. A later explicit Operator decision or integration boundary owns any source chronology. |

Checkpoint receipts carry exact before and resulting revisions. Legacy projection marks newly checkpoint-required route and planning artifacts stale until the saved file is present at the selected head. The structured Work Intake projection exposes persisted SourceCheckpoint state and resulting revision. None of these paths performs Git operations from renderer code.
