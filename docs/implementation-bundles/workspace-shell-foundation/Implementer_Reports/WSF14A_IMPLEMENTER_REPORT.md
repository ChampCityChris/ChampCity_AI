## Implementation and authority

ImplementationAttempt is a durable mutable prepared/running/completed/abandoned envelope. ImplementationRecord remains an immutable terminal result; Pending is not an ImplementationRecord outcome. Typed implementation_attempt_for and attempt_result relationships retain ownership and result provenance. Generic creation, revision, supersession and relationship creation cannot bypass the attempt commands. No physical SQLite schema, dependency or migration changed.

prepareImplementationAttempt captures the exact approved WorkItem version, Workflow, its linked BoundedSolution, applicable Criteria, Phase/dependencies, governance records and SourceBaseline/binding identity. It stores exact entity/version sources and a deterministic reservation digest, rather than copying Markdown authority. Greenfield resolves the WorkItem's implements edge, because different Phases have distinct solutions. Execution contracts use that same exact solution selection.

Repeated preparation returns the matching prepared identity after checking its reservation. A changed contract/source revision abandons the previous prepared attempt and creates a fresh identity. Preparation changes neither WorkItem state nor source preparation state; it does not start Codex, create a worker, materialize a checkout or create an ImplementationRecord. Known binding line/checkout changes fail closed for inspection. Materialization-only binding revisions can preserve the reserved baseline/current source revision.

The exact Codex path reserves/reuses the attempt before source materialization, checks reservation freshness before preparation, rechecks it at begin, and uses ImplementationAttempt.id as executionRef, evidence-packet identity and checkpoint boundary. Existing direct shared Run orchestration auto-prepares an attempt and returns that durable executionRef; callers carry it to finish. Pending readiness is a pure reservation read. Running SQL state without a live session reports recovery/inspection required and cannot start a second execution.

Completion atomically creates one immutable ImplementationRecord with executionRef equal to attempt.id, links attempt_result, marks the attempt completed and preserves existing WorkItem outcome transitions. Repeating the exact result returns the same record; conflicting evidence fails closed. Tester still targets ImplementationRecord. Existing implementation/Tester/source-checkpoint semantics remain in place.

getImplementationAttemptReport reconstructs Pending and completed reports from SQL, including reserved entity versions, exact report identity, immutable outcome/summary/deviations/blockers/risks, and linked source checkpoints. It has a stable Markdown filename and deterministic content, supports the standard implementation-report renderView path, and is available through bounded IPC/preload get/prepare ports. Markdown export is a non-authoritative document projection. No canonical report file, JSON sidecar or renderer-local prepared flag is introduced.
