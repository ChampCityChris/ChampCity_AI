# WC31 — Project Architect Interview Draft-Ingestion Pilot Cutover

Status: Planned; not authorized for Implementer execution  
Git mutation: prohibited

## Purpose

Adopt the WC30 shared Architect draft-ingestion and canonical-promotion subsystem for exactly one production output flow:

```text
Project Architect Interview
```

This is the first production pilot. It must prove the shared infrastructure in the running application before any additional Architect-output flow is adopted.

Do not implement this Work Card until the Operator explicitly approves execution after reviewing WC30 deterministic results and confirming that the generic MCP action is available:

```text
artifact_toolbox.create_markdown_artifact
```

## Scope Boundary

WC31 changes only the Project Architect Interview output path.

It must not change:

```text
Project Planning
Phase Map
Phase Interview
Phase Planning
Work Card Plan
Formal Work Card
Repair Work Card
```

It must not migrate, rewrite, transform, or reconcile any existing Architect Interview file.

Only a fresh Architect Interview output request created after the pilot cutover uses the new mechanism.

## Objective

Replace the current Project Architect Interview body-save path with this single flow:

```text
ChampCity A/I prepares a fresh Architect Interview draft submission
→ embedded ChatGPT writes the body-only draft through artifact_toolbox.create_markdown_artifact
→ the WC30 shared status service detects the draft
→ the WC30 shared promotion service validates the body
→ ChampCity A/I constructs canonical Interview metadata
→ ChampCity A/I writes and verifies the final canonical Interview
→ consumed draft is removed
→ final Pending Interview appears in the existing Operator review surface
```

## Required Change 1 — Register One Production Output Definition

Add one production registry definition for Project Architect Interview.

The definition must supply only Project Architect Interview-specific information required by the WC30 contract:

```text
outputKind
owningWorkspaceId
single output slot
body validator
final target resolver
canonical metadata builder
post-promotion selection behavior
```

Do not modify the WC30 generic draft inspection, promotion, cleanup, transaction, or status algorithms merely to accommodate this pilot unless a concrete foundation defect is proven. Any foundation defect must be reported and resolved through a separate repair card rather than hidden inside the pilot.

## Required Change 2 — Fresh Draft Submission Handoff

A fresh Project Architect Interview handoff must provide:

- the exact temporary draft path generated by ChampCity A/I;
- body-content requirements;
- the generic MCP invocation for `artifact_toolbox.create_markdown_artifact`;
- `overwrite: false`;
- no canonical metadata;
- no final canonical output path supplied to the MCP;
- no `handoffKind` submission action;
- no hash, digest, checksum, token, or hidden authorization value;
- a statement that the workflow remains incomplete until the draft is created and ChampCity A/I promotes it.

The handoff must not instruct the LLM to call `submit_handoff_outputs` or any retired domain-specific save action.

## Required Change 3 — Application-Owned Canonical Interview Construction

The production definition must preserve the current ChampCity A/I meaning of the final Project Architect Interview:

- final path family;
- artifact type;
- participation role;
- identity;
- source revisions;
- artifact revision behavior;
- workflow data;
- Pending disposition for a fresh review output;
- existing Operator review controls;
- existing freshness behavior.

The LLM and MCP must not construct or validate those fields.

WC31 must not introduce new review-state restrictions or content-quality scoring.

## Required Change 4 — Remove Only the Retired Interview Save Path

After the new Project Architect Interview pilot path is connected, remove only the production code whose sole purpose is the old direct Interview body-save path.

Expected candidates include the current Interview-specific save function, IPC/preload method, prompt wording, and any output polling branch that becomes redundant because the shared WC30 status path now owns the behavior.

Do not retain:

- an old-save fallback;
- a hidden retry using the old action;
- dual writes;
- compatibility with body-only `submit_handoff_outputs`;
- a manual textarea or file-copy fallback.

Do not remove shared code used by other current output flows.

## Required Change 5 — Existing Files Are Evidence, Not Migration Inputs

Existing Project Architect Interview files remain untouched.

WC31 must not:

- rewrite them into a new shape;
- add draft markers to them;
- synthesize draft submissions from them;
- use them to claim the pilot succeeded;
- delete or archive them automatically.

A new pilot handoff and new draft submission must be generated from the current application workflow context.

## Required Change 6 — Running-Product Pilot Validation

Operator validation must prove the complete fresh-output path:

```text
prepare fresh Interview handoff
→ embedded ChatGPT receives exact temporary draft path
→ ChatGPT calls create_markdown_artifact
→ only the temporary draft is created by MCP
→ ChampCity A/I detects the draft automatically
→ ChampCity A/I promotes the final canonical Interview
→ draft disappears after successful verification
→ final Interview appears as Pending
→ Operator can review and apply disposition
```

Validation must also prove:

- a malformed draft remains visible as a promotion failure and is not converted into a final Interview;
- retry after correcting the draft uses a fresh submission rather than overwriting the failed draft;
- no old Interview save path is invoked;
- no other Architect-output flow changes behavior.

## Non-Scope

Do not adopt any second output flow.

Do not create a generic rollout framework beyond WC30.

Do not migrate current files.

Do not add fallback behavior.

Do not change MCP implementation.

Do not broaden application governance or add quality scoring.

Do not perform Git operations.

## Required Proof

Record each item as `Proven`, `OperatorValidationPending`, or `NotProven`.

1. Exactly one production definition is added: Project Architect Interview.
2. The definition uses the WC30 shared services without duplicate draft inspection or promotion logic.
3. A fresh handoff uses only `artifact_toolbox.create_markdown_artifact` and one application-generated draft path.
4. MCP writes only the temporary draft.
5. ChampCity A/I constructs and writes the complete final canonical Interview.
6. Existing Interview metadata meaning and review behavior are preserved.
7. Successful promotion removes the draft only after verification.
8. Failed promotion retains the draft and creates no final output.
9. Existing Interview files are not migrated or modified.
10. The old Interview-specific output-save path is removed after cutover.
11. No fallback, alias, dual write, old-action retry, or manual import exists.
12. Other Architect-output flows remain unchanged.
13. Typecheck, build, and complete tests pass in the normal Windows lane.
14. Operator running-product validation is completed before any additional output adoption card is authorized.
